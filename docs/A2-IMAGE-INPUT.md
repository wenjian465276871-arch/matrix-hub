# A2 图片输入方案

> 版本 v0.1 · 状态：草案 · 日期：2026-10-18
> 关联：开发计划 v1.9 §2.1（A2 输入）、`deepseek-flash` 元数据 `input_modalities: ["text","image"]`
> 决策：#11（见开发计划 §7.1）

## 1. 为什么做

原方案 A2 只接受「粘贴文本」。但工艺工程师手上的东西，多数不是干净的纯文本：

- 工艺文件是 PDF / Word 导出的**版面**，直接复制会丢表格结构、丢标注位置；
- 现场要记录的往往是**截图**（设备界面、图纸局部、端子排照片）；
- 让人"用文字描述一张图"，本身就是信息损耗最大的一步——他看到的和写下的，中间隔着一层转述。

所以图片输入的价值不在"多一个入口"，而在**少一道转述**。转述一少，后面的判据、图示、安全提示才可能准确。

## 2. 边界（先说清楚不做什么）

| 做 | 不做（v1） |
|---|---|
| PNG / JPEG / WebP 位图 | PDF 直接解析（前端先转图，属 backlog） |
| 印刷体中文、数字、常见符号 | 手写体（不承诺，误识别代价太高） |
| 表格、标注、圈注的**文本与结构** | 复杂装配图的几何语义理解 |
| 图形符号：仅识别能映射到现有 7 个原语的 | 自由绘制 SVG / 生成新原语 |
| 识别结果进草稿，人工确认后发布 | 自动发布 |

## 3. 总体链路

```
图片上传
  → 预处理（格式校验 / 尺寸与清晰度门槛 / EXIF 剥离 / 重编码）
  → 版面切分（整图 + 局部放大：表格区、标注区、小字区）
  → 双通道识别（OCR 文本层 ‖ 多模态理解层）
  → 差异比对 + 结构化（严格 Guide JSON Schema）
  → 三层校验（结构 / 语义 / 回溯）
  → 人工确认页（原图与字段并排，点字段定位原图）
  → 草稿入库 → 现有 A2 流程（渲染 / 发布）
```

**关键点：不是"一次调模型出结果"，而是"两通道 + 可回溯"。** 单通道识别错了你不知道错在哪；双通道不一致的地方，正好是需要人看一眼的地方。

## 4. 输入规格（硬门槛，服务端强制）

| 项 | 要求 | 不满足时 |
|---|---|---|
| 格式 | PNG / JPEG / WebP（按魔数判断，不信任扩展名） | 415 |
| 单文件 | ≤ 5 MB（路由 body ≤ 6 MB） | 413 |
| 像素 | 长边 ≥ 1600 px 建议；**< 1000 px 直接拒绝** | 422 + 提示重拍/重截 |
| 长宽比 | 0.3 ~ 3.3（极窄长条多为截断） | 422 |
| DPI | 扫描件 ≥ 200 dpi（由像素与物理尺寸推算，无法推算时只做尺寸判断） | 警告，不阻断 |
| 张数 | 单次 ≤ 3 张 | 422 |
| 内容 | 关键数值被水印/马赛克遮挡 | 无法自动判断 → 确认页提示 |

**为什么卡 1000px：** 小字（如 `M6×12`、`0.8 N·m`）在 1000px 以下的图里通常只有 8–10 px 高，任何 OCR 都不稳。与其后面纠错，不如前面拒收。

EXIF 一律剥离后重编码（隐私 + 去潜在载荷，与计划 §11.3.2 一致）。

## 5. 识别策略

### 5.1 分层切图，而不是整图硬啃

1. **整图**：建立全局结构（标题、章节、步骤顺序）。
2. **局部放大**：检测表格区、标注引出线密集区、字号最小的区域，按 2–3 倍放大后单独送识别。
3. **重叠冗余**：局部块与整图保留 15% 重叠，避免切在字上。

### 5.2 双通道交叉

| 通道 | 作用 | 输出 |
|---|---|---|
| OCR（版面分析） | 提供**原文文本与坐标** | 文字块 + bbox + 置信度 |
| 多模态理解 | 提供**语义与结构**（哪句是动作、哪个是判据） | 结构化 JSON 草稿 |

两者比对：
- 文本一致 → 高可信；
- 文本不一致 → 标 `conflict`，进确认页；
- 语义层出现 OCR 层没有的数值 → **以 OCR 为准并标 `unverified`**，禁止凭空补数。

### 5.3 表格

先出结构（几行几列、合并单元格），再逐格填值。**空单元格保持空，不推测。** 推测出来的数值比缺失更危险。

### 5.4 图形符号

只识别能映射到现有原语的（状态灯、仪表、端子序、力矩值）。映射不了的一律**保留原图区域作为图片位**，由人工决定是否补图示。不臆造 SVG。

## 6. 校验与纠错（三层）

| 层 | 检查什么 | 失败处理 |
|---|---|---|
| **L1 结构** | Guide JSON Schema（已有契约） | 自动重试 1 次；仍失败返回 `schema_error` 与定位 |
| **L2 语义** | 单位与量纲、量程合理性、判据区间自洽、步骤序号连续 | 标 `suspect`，不阻断但要人确认 |
| **L3 回溯** | 每个关键字段必须能指回原图位置（bbox 或原文行） | 指不回 → 标 `unverified`，确认页强制勾选 |

**三层都过也不自动发布。** 数值类判据（range）与安全提示必须人工确认——这是责任边界，不是流程洁癖。

典型纠错规则（可配置，不写死在代码里）：

- 力矩：车门类螺栓常见 0.5–30 N·m；识别出 300 视为量级错误 → `suspect`
- 间隙：常见 0.5–10 mm；识别出 0.02 且单位为 mm 时，提示可能漏了"塞尺规格"而非间隙值
- 单位缺失：数值判据缺单位直接判 L1 失败（契约已强制）

## 7. 人工确认页（不可省的一步）

- 左：原图，支持缩放与框选高亮；右：结构化字段列表。
- 点任一字段 → 左图对应 bbox 高亮；点图上文字 → 右侧字段滚动定位。
- 三种标记色：`ok` / `suspect`（黄）/ `unverified`（红）。
- **"全部确认"按钮只在无红色项时可用**；黄色项需要逐个点过。
- 确认动作记入作业记录（谁、何时、改了哪个字段），便于事后追责与统计误识别率。

## 8. 与现有流程的接入

### 8.1 端点

```
POST /api/electro/uploads        # 上传图片，返回 asset_id（校验格式/尺寸/大小）
POST /api/electro/extract        # {asset_ids:[...]} → 返回 draft Guide + provenance
POST /api/electro/generate       # 现有文本入口不变
```

`extract` 与 `generate` **共用同一个 Guide Schema 与同一套校验**，只是前置不同。这是能"接入现有流程"的根本原因——下游完全不用感知输入形态。

### 8.2 数据结构增量（向后兼容）

```jsonc
// Guide.meta 新增可选字段
"source_type": "text" | "image",

// Criterion / Step 新增可选 provenance（仅图片输入时有）
"provenance": {
  "asset_id": "a_xxx",
  "bbox": [x, y, w, h],       // 归一化到 0–1
  "raw_text": "0.8 N·m",
  "confidence": 0.92,
  "flag": "ok" | "suspect" | "unverified"
}
```

均为可选字段，文本输入路径不受影响；旧数据无需迁移。

### 8.3 存储

- 原图存 `app_data/uploads/<asset_id>.<ext>`，重编码后写入，不存原始字节；
- 保留期 30 天（与访客草稿一致），确认发布后仅保留引用；
- 单张上限 5 MB，单日总量设配额（防刷）。

## 9. 关键步骤与顺序

| 步 | 内容 | 可交付 |
|---|---|---|
| 1 | 上传端点 + 服务端规格校验 + 重编码 | 能收图、能拒不合格的图 |
| 2 | 预处理切图（整图/表格区/小字区） | 可视化切图结果，人工看是否切对 |
| 3 | 双通道识别 + 差异比对 | 3 份真实工艺截图跑通，输出草稿 JSON |
| 4 | 三层校验 + 确认页数据契约 | 前端能拿到 `flag` 与 `bbox` |
| 5 | 确认页（前端）与记录 | 端到端可用 |

每步独立可验收，不搞大爆炸集成。

## 10. 预期效果（可量化）

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 字段抽取准确率 | ≥ 90% | 3 份人工标注样例，逐字段比对 |
| 数值类误读 | **0 容忍** | 必须人工确认；统计确认页改字段次数 |
| 端到端耗时 | ≤ 60 s（3 张图） | 服务端计时 P50/P95 |
| 人工描述工作量 | 相比纯文本输入下降 ≥ 50% | 同样一份工艺文件，两种方式计时对比 |
| 一次通过率（无需改字段） | ≥ 60% | 确认页统计 |

## 11. 成本

单次抽取约 3 张图 + 2 轮局部放大 = 5 次视觉调用，按 `deepseek-flash` 图片计价估算，单份 ¥0.05–0.15 量级。日预算 ¥3 熔断不变；图片路径单独计数，便于观察是否被刷。

## 12. 风险

| 风险 | 应对 |
|---|---|
| 模型"读懂"了但读错数字 | L3 回溯 + 强制人工确认，不自动发布 |
| 版面复杂（多栏 + 表格 + 引出线） | 分层切图；仍失败则降级为"只抽文本，结构人工补" |
| 图片模糊/压缩失真 | 前置 1000px 门槛；确认页提示重拍 |
| 成本被刷 | 每 IP 限流 + 日预算 + 单日上传总量 |
| 依赖单一模型的视觉能力 | 抽象 `VisionProvider`，可换通义千问 VL 作备选 |

## 13. 对现有计划的影响

- **范围**：A2 输入从"仅文本"扩展为"文本 + 图片"，属**增量**，不改下游契约。
- **工期**：P1a 内插入约 2–3 天（上表 5 步），或拆到 P1b 之后单独做；建议**先做步 1–2**（收图 + 切图），把识别质量验证放在有真实截图之后。
- **契约**：Guide Schema 只加可选字段，`schema_version` 维持 1.0。
- **不做**：PDF 直接解析、手写体、自动发布。
