# 交互与体验规范（as-built）

> 版本 v1.1 · 最后更新：2026-10-30 · 适用范围：`apps/electro-assist/web`
> 本文只定义**行为**：页面、状态、反馈、边界。视觉值见 `UI.md`，代码结构见 `FRONTEND.md`。
> 写的是已上线的实际交互；原设计里没做的，集中列在 §8。

## 1. 信息架构

| 层级 | 实际路由（base `/apps/electro-assist/`） |
|---|---|
| L0 | 指导书库 `/` —— 落地页，A2 产物的消费入口 |
| L1 | 生成 `/new` → 指导书 `/guide/:id`（**草稿与已发布同页**，草稿顶部挂"未发布"横幅） |
| L1 | 引导 `/run/:sid` → 记录 `/record/:sid`（**无选择页**：从详情页"开始引导作业"直接建会话） |
| L1 | 排查 `/diagnose`（一次性检索，支持 `?symptom=&guide=&step=` 从 A1 转入） |
| — | 关于页、多轮排查：**不存在**（配额余量直接显示在 `/new`） |

跨模块路径：

| 路径 | 传参 |
|---|---|
| A2 指导书 → A1 | `POST /sessions` 建会话 → 跳 `/run/:sid`；指导书由会话携带 |
| A1 异常 → B | `/diagnose?symptom=…&guide=…&step=…`，排查页顶部显示"来自作业记录：第 N 步异常" |
| A1 记录 → 指导书 | `/guide/:id`，闭合「A2 看懂 → A1 照做 → B 兜底 → 回看」 |
| B 结论 → 记录 | `report()` 按 `session_id` 关联，记录页与导出 HTML 只读展示「关联排查结论」 |

导航只有一条顶部 48px 深色条（品牌 + 生成 + 排查 + 返回门户），不做底部 tab：
A1 底栏要独占拇指区，双底栏会把它挤出可达范围。

## 2. 三条核心流程

### 2.1 A2 生成（异步 5–30s）

| 步 | 行为 | 反馈 |
|---|---|---|
| 粘贴原文 | 非空 + 长度合规即解禁；页面显示当日/当小时余量 | 超配额提前禁用并说明原因 |
| 提交 | 按钮转"生成中"，**不切页**；按 `poll_after_ms` 轮询 `GET /jobs/{id}` | 成功自动跳 `/guide/:id` |
| 失败 | 错误号 + 可读原因 +「重新生成」；`retry_of` 满足条件不扣配额 | 队列满 503、预算耗尽 429 `budget_exhausted` |
| 草稿 | 顶部"未发布 · 仅凭链接可见"横幅 | 生成失败不留半成品 |
| 发布 | **无界面**：服务器 CLI `python -m scripts.publish --publish <id>` | 无鉴权不做后台 |

轮询用 `setTimeout` 链（不是 `setInterval`，慢响应不堆积），失败退避 2s。

**现场素材（可选）**：文本区下方可加最多 4 张截图/照片。

| 步 | 行为 | 反馈 |
|---|---|---|
| 选图 | 一次可选多张，逐张上传；单张 ≤5MB、长边 ≥1000px | 超限/格式不符只报该张，不中断其余 |
| 写说明 | 每张一句说明（≤60 字），留空则自动「图 N」 | 说明只用于排版标注，不送模型 |
| 提交 | 随生成请求带 `asset_id + caption`，素材进草稿「素材区」 | 图不在盘上时 422 `asset_not_found`，不扣配额 |
| 选区域 | 点「选择区域」→ 弹层列出整图/表格行带/表格区/密集文字块 →「用这块」复制成新素材 | 每源图最多采纳 6 次；关弹层不改变已选素材 |
| 识别 | 点「识别图中内容」→ 服务端单通道识别 → 面板显示转录原文、待核对项和缺口；确认后「填入工艺文本」 | 结果只回填文本框，不自动生成；无 Key 时提示 `vision_not_configured` |
| 归位 | 生成完在草稿页每张图选「素材区 / 第 N 步」，保存即生效 | 已发布 409；不能清空（`assets_required`） |

为什么不自动分配：模型没看过图，让它猜位置就是把"这图是哪一步的"变成幻觉。

### 2.2 A1 引导（现场高频）

| 步 | 行为 | 反馈 |
|---|---|---|
| 建会话 | 设备编号/位置/备注选填；输入即建，不加确认层 | 每 IP 10 次/时 |
| 执行单步 | 图示在上、判据在下、底部固定 48px 操作条 | 仅 1 张卡"进行中"，切卡时页面滚动到卡顶 |
| 填判据 | 失焦 + 提交双次校验；`inputmode="decimal"` | 超限：红描边 + 图标 +「超出上限 24.0 V」，**不阻断输入** |
| 提交 | 失败保留已填值；`Idempotency-Key: {sid}:s{seq}:a{attempt}` 幂等重试 | 通过 / 异常 / 需复测 |
| 异常分支 | 转故障排查 / 复测 / 停止作业 | "停止作业"危险色 + 二次确认（含记录编号） |
| 结束 | 生成记录：每步实测值、每步耗时、异常链、关联排查结论、总时长 | 记录页可打印、可「导出 HTML」（自包含文件，离线可读） |

判定**全在服务端**：客户端传 `verdict` 会被忽略；`fail`/`warn` 不推进，`pass`/`manual` 才前进。
这就是"失败不推进、复测留 attempt"的实现方式——界面只负责展示结论。

### 2.3 B 排查（一次性检索，非流式）

| 步 | 行为 |
|---|---|
| 描述现象 | 单行输入，≥1 条文本即可提交；从 A1 转入时预填症状并标注来源 |
| 两种模式 | 快速检索（一句现象 → 候选）与逐步诊断（故障树逐项检查，实测值回填，服务端收敛） |
| 提交 | 一次性 JSON；快速模式可能带 1–2s 受限重排 |
| 命中 | 结论卡：条目标题 + 检查顺序（有序列表）+ 升级条件 + 安全提示 +「来自人工整理的知识库」 |
| 未覆盖 | warning 卡分两种文案：`system_not_covered`（子系统未收录）/ `no_match`（有收录但现象不接近），保留输入 |
| 多轮收敛 | **不做**：现场要"下一步查什么"，重查就再提交一次 |

## 3. 交互规范

| 项 | 规则 |
|---|---|
| 校验时机 | 数值：失焦 + 提交；枚举：选择即校验；长文本：仅提交；必填缺失：提交时定位并 focus 首个缺失项 |
| 错误文案 | 三段式「哪里错 + 怎么改 + 当前值」，例：「实测值 24.6 V 超出上限 24.0 V，请复测；仍超限请标记异常」。错误号放次要行 mono |
| 错误语义 | `lib/errors.ts` 按服务端 `code` 映射文案（`rate_limited` / `passcode_invalid` / `budget_exhausted` / `duplicate_check` / `value_invalid`…），未知 500 展示"错误号 ref" |
| 危险确认 | 停止作业：标题含对象名 + 后果说明，主按钮危险实心，**默认焦点在取消** |
| 禁用 vs 加载 | 加载：原宽 + 左侧 14px spinner，不位移；禁用：同行说明原因（"请先粘贴工艺文本"），不许只有灰按钮 |
| 限流态 | 非错误。文案说明"本小时 2 次已用完"，主操作置禁用；**不提供可点的"重试"**（对着 429 连点只会更糟）；"重试不扣配额"只出现在 5xx/timeout 卡上 |
| 输入适配 | 判据框 `flex:1` + `min-width:120px`，超长数字只在 input 内横向滚动；单位 ≤3 字符（V/A/Ω/Hz/kW/mA），全称走 `aria-describedby`；不用长按/滑动手势（手套失效） |
| 底部操作条 | h48 + padding 8/16 + `env(safe-area-inset-bottom)`；主按钮独占整行；内容底部预留 64px 防遮挡末卡 |

## 4. 响应式

| 区域 | 手机 <640 | 平板 640–1023 | 桌面 ≥1024 |
|---|---|---|---|
| 容器 | 单列，padding 16 | 单列，padding 16 | `--w-content` 860 居中 |
| 导航 | 短品牌 + 3 项，`nowrap` | 全品牌 + 3 项 | 同 |
| A1 步骤 | 单列：图示 → 判据 → 底栏 | 单列 | 内容列居中，图示 ≤520 |
| B | 单列 | 单列 | 单列（表单 + 结果，不做两栏对话） |
| 表格 | 转"标签-值"堆叠，不横向滚动 | 保留表格 | 全量 |

触摸目标：通用 ≥44×44，A1 现场全部 48×48。软键盘：聚焦时 `scrollIntoView({block:'center'})`。
拇指区纪律：A1 自上而下锁定「内容 → 图示 → 判据 → 底栏」，新元素不得插在判据与底栏之间。

## 5. 可访问性

| 项 | 现状 |
|---|---|
| 对比度 | 正文 ≥4.5:1、判据数值 ≥7:1（令牌取值时已按此选色） |
| 语义 | 每页唯一 `h1`；图示 SVG 全部 `role="img"` + `aria-label`；模式切换 `role="tablist"/tab` + `aria-selected` |
| 键盘 | Tab 顺序 = 视觉顺序；判据框 Enter 提交；模态层（停止作业确认）用原生 `dialog` 语义 |
| aria-live | **局部**：生成轮询状态区 `aria-live="polite"`；无全局播报双区 |
| 减少动效 | `prefers-reduced-motion` 全局压到 0.01ms |
| 色盲 | 状态胶囊三重编码（图标 + 文字 + 颜色）；超限除红色必带图标与具体数值 |
| 未做 | skip-link、页面切换播报、`<caption>` 视觉隐藏表头（弹层 focus trap / Esc 回流已实现） |

## 6. 性能与感知

| 场景 | 策略 |
|---|---|
| 首屏 | 单文件 CSS `<link>`（**不内联**，CSP `default-src 'self'` 不放宽）；库页 ≤12 条；其余路由懒加载 |
| 骨架 | 长任务用骨架，行高 = 真实字段；>800ms 才转骨架，之前按钮内 spinner |
| 长列表 | 一次拉取 ≤50 条，不分页（当前 5 份）；到 20 份以上再加「加载更多」，不用无限滚动 |
| 图示 | 内联 SVG，零请求；未注册类型降级无图版 |
| 打印 | 两套 print CSS 随路由加载；记录页异常链单独成节 |

## 7. 三条关键取舍

1. **不设底部 tab bar**：现场 48px 操作条与拇指区是安全相关需求，导航便利性让位。
2. **超限提示但不阻断**：真实读数是事实，阻断会诱导工人改数，风险远大于提交一个超限值。
3. **B 不做流式**：知识库 18 条、检索 P95 个位数毫秒，没有可流的内容；为一屏即时结果搭 SSE 解析与重连是给自己造复杂度。若将来要流式，仍选 fetch 流而非 `EventSource`——只有前者能读到 429 与 `retry-after`。

### 7.1 本轮补齐（2026-10-30）

| 项 | 实现口径 |
|---|---|
| 生成取消 | 轮询期给「停止等待」：停定时器 + 忽略结果，**不打断服务端**（LLM 调用断不了，也不该假装断）。取消后如实说明「任务仍在后台跑，跑完只进草稿箱」，不承诺"已取消" |
| 暗色皮肤 | 只在抽屉底部手动切，落地 `localStorage['electro-theme']`，不跟随系统；暗色下实心块自动换深色字 |
| 暗色逃生条 | 只在 A1 与 `?from=run` 的 B 出现，sticky 占文档流；一键切回亮色后 120ms 淡出；不进打印 |
| 抽屉导航 | 窄屏只留 `⋯`，全屏抽屉含 4 入口 + 外观；Tab 循环 / Esc / 焦点回流 / 锁滚动 |

## 8. 未实现的交互（登记，不假装存在）

| 项 | 原设计 | 现状 | 处置 |
|---|---|---|---|
| 超限行内「仍要提交」 | 提示但不阻断，另给强制提交入口 | 提示有，**强制入口没有**：提交后服务端判 `fail`，走复测/异常分支 | 服务端判据是红线，前端不提供绕过按钮 |
| `job_id` 刷新续接 | `sessionStorage` 存 job，刷新接着轮询 | 刷新回 `/new` 重新提交；已扣配额不退，`retry_of` 可申请豁免 | 先做后端可恢复，再做前端续接 |
| 429 倒计时 | 秒级倒计时 + 禁用 + `aria-describedby` | 只有文案，无倒计时 | 倒计时会带来读屏连播问题，等有真实限流投诉再做 |
| 草稿修正 / 界面发布 | 逐字段修正 + 发布按钮 | 无修正界面，发布走 CLI | 决策：无鉴权不做后台 |
| 指导书搜索 | 列表 + 搜索 | 仅列表（6 份数据） | 到 20 份再说 |
