# ADR-0001：单仓 + 单镜像 + Caddy 统一入口

- 状态：已接受
- 日期：2026-10-17
- 决策人：项目所有者（单人项目）

## 背景

现状是宿主机 nginx 直接服务多个站点目录，另有独立的 Docker 容器跑历史项目。问题有三个：

1. **部署靠手工**：改一次配置要 ssh 上去改文件、reload，没有版本记录，回滚靠记忆。
2. **形态不一致**：静态站点在宿主机、部分服务在容器里，证书与安全头分散在两套配置中。
3. **入口不统一**：多个端口对外暴露，任何一条规则漏配就是一个洞。

目标：把"提交即上线、失败可回滚"做成常态，且不引入超出单机容量的复杂度。

## 决策

1. 四个模块合并为**单仓**（`apps/*`），一次构建产出**一个镜像**。
2. 镜像内用 **supervisord** 托管 Caddy 与两个后端进程。
3. **Caddy** 作为唯一公网入口，负责 TLS、HTTP→HTTPS 跳转、安全头、CSP、反向代理；后端只监听 `127.0.0.1`。
4. 镜像由 **CI 构建**并推送到私有镜像仓，服务器只做 `pull` + `compose up`，**不编译**。
5. 部署脚本带健康检查，失败自动回滚到上一个镜像标签。

## 备选方案与放弃原因

| 方案 | 放弃原因 |
|---|---|
| 维持 nginx 直服 | 无法做到"一次构建、原子回滚"；配置漂移无法审计 |
| 每模块一仓 | 版本对齐成本高，一次发布要协调多个仓库与流水线 |
| 多容器 compose（每服务一容器） | 2C2G 上容器开销与运维复杂度不划算；进程级隔离对本项目足够 |
| 服务器本地构建 | 大陆网络拉基础镜像与依赖不稳定，且把构建风险带进生产机 |
| 用 Nginx 替代 Caddy | 证书自动续期与配置校验要额外组件；Caddy 的 Caddyfile 更短、可 `validate` |

## 后果

**正面**

- 发布 = 一个镜像标签，回滚 = 切回上一个标签，两者都是分钟级。
- 公网只开 22/80/443，后端端口不出网。
- 安全头、CSP、压缩、缓存策略集中在一个文件里，可评审、可 diff。

**负面 / 需要接受的代价**

- 单进程组故障会一起挂：Caddy 挂了两个 API 也访问不到（进程级隔离，非容器级）。
- 镜像体积大于单模块镜像；需要控制基础镜像与依赖。
- 任一模块的依赖升级都会触发整体重建，需要依赖锁定（`uv.lock` / `package-lock.json`）。

**约束**

- 基础镜像按 digest 固定；第三方 Action 固定到 commit SHA。
- 服务器不使用 Docker socket 挂载，不加 `--privileged`。
- 镜像标签使用 git commit SHA，禁止 `latest` 上线。
