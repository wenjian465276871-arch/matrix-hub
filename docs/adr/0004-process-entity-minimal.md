# ADR-0004：工艺实体只做「最小落库」

- 状态：已接受（2026-11-03）
- 影响范围：`POST /processes`、`GET /processes/{id}`、`POST /processes/{id}/generate`、迁移 v7
- 取代：决策 #22 ④「不建工艺实体」中的**一部分**——不建"工艺版本/工位/工具"的完整模型，但保留原文

## 背景

计划 §3.5 写的是「创建工艺」，落地时（决策 #22）收窄成无状态预检：规则解析、不落库、不产出 Guide。
理由是"没有消费者，多一个实体只是空壳"——`/generate` 直接吃文本，预检只服务提交前自检。

2026-11-03 补消费者时，这个判断需要修正：**详情页要能拿同一份文本重新生成**。
原文此前只活在内存队列里，任务一结束就没了；用户要重跑只能回生成页重新粘贴，
而粘贴出来的"同一段文本"往往已经和当初不是一份东西（改了两个字，判据就变了）。

## 决策

**只存原文与派生标题，不存预检结果。**

```
processes(id, title, system, text, chars, input_sha256, created_at, updated_at)
jobs.process_id      -- 这次生成用了哪份工艺（审计）
guides.process_id    -- 这份指导书由哪份工艺生成（再生成入口）
```

具体约束：

1. **不存预检结果**。预检是解析规则的确定性输出，存下来必然与规则漂移——改了正则，
   旧行还是旧结论。要预检就重新算，毫秒级。
2. **不建版本链**。没有"工艺 v1/v2"：文本变了就是另一份工艺。版本链需要 diff、回滚、
   迁移语义，而当前唯一的消费者只关心"原文是什么"。
3. **保留 30 天、写时清理**，与访客草稿一致；仍被指导书引用的行不删。
   不新增 cron——一个"必须记得配"的定时任务是运维负债。
4. **`save=false` 仍是纯预检**，老调用方行为不变；`/generate` 自动落一份，
   `retry_of` 复用原工艺而不是复制。
5. **配额不因入口而变**。`POST /processes/{id}/generate` 走同一个 `generation.submit`，
   否则这里就是绕过限流的后门。

## 后果

- 详情页有了「再生成一份草稿」，不必回生成页重粘；代价是每次生成多一次 INSERT 与一次过期清理。
- 访客文本多了一处存储面（30 天，随机 id 不可枚举），与草稿同级。
- 迁移只加表加列，旧版本代码不回滚也安全（SQLite `SELECT *` 多列无害）。

## 备选与否决理由

| 备选 | 为什么不选 |
|---|---|
| 建完整工艺模型（工位/工具/版本链） | 消费者只有一个字段：原文。其余字段预检能算、Guide 里也有，存两遍就是两处漂移 |
| 完全不落库，靠 URL 传文本 | 文本最长 20,000 字，URL 放不下；且会把访客内容写进浏览器历史与代理日志 |
| 只存 hash，原文从 job 表取 | job 会被清理（90 天）、且不保证保存原文；"再生成"会在某个时间点突然失效 |
